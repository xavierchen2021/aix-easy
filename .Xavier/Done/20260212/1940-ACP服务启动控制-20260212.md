# ACP 服务启动控制

## 概述
当前 opencode ACP 服务是懒加载的（首次发 AI 消息时才建立连接），用户无法主动管理 ACP 服务的生命周期。需要在设置中添加手动启动/停止按钮和自动启动选项。

## 当前实现

```mermaid
sequenceDiagram
    participant U as 用户
    participant NW as 笔记窗口
    participant AI as AIService
    participant ACP as opencode acp

    U->>NW: 发送 AI 问题
    NW->>AI: sendQuestion()
    AI->>AI: sendViaOpencode()
    AI->>AI: ensureACPConnection()
    
    alt ACP 未连接
        AI->>ACP: 启动 opencode acp 进程
        AI->>ACP: connect() + createSession()
    end
    
    AI->>ACP: prompt()
    ACP-->>AI: agentMessageChunk 流式回答
    
    Note over AI,ACP: ⚠️ 没有手动启动/停止<br/>⚠️ 没有自动启动选项<br/>⚠️ 没有连接状态显示
```

## 方案

### 🚀推荐方案 方案一：在设置中添加 ACP 服务控制面板

```mermaid
sequenceDiagram
    participant U as 用户
    participant Set as 设置页面
    participant AI as AIService
    participant ACP as opencode acp
    participant AD as AppDelegate

    alt 自动启动模式
        AD->>AI: 应用启动时 connectACP()
        AI->>ACP: 启动进程 + 连接
    end

    alt 手动启动模式
        U->>Set: 点击"启动 ACP 服务"
        Set->>AI: connectACP()
        AI->>ACP: 启动进程 + 连接
        Set->>Set: 显示连接状态：已连接 ✅
    end

    alt 手动停止
        U->>Set: 点击"停止 ACP 服务"
        Set->>AI: disconnectACP()
        AI->>ACP: 断开 + 终止进程
        Set->>Set: 显示连接状态：未连接 ⚪
    end
```

**优点：**
- 用户可控，灵活选择自动或手动
- 自动启动可减少首次 AI 查询延迟
- 连接状态一目了然

**缺点：**
- 自动启动会多占一个后台进程

## 测试用例

1. **手动启动**：进入设置 → opencode 配置 → 点击"启动 ACP 服务" → 状态变为"已连接"
2. **手动停止**：点击"停止 ACP 服务" → 状态变为"未连接"
3. **自动启动**：开启"应用启动时自动启动" → 重启应用 → ACP 自动连接
4. **首次使用无延迟**：ACP 已连接时发 AI 消息 → 立即收到回答

## 任务总结与结论

已完成 ACP 服务启动控制功能的实现，包含以下核心改动：

1. **手动 JSON-RPC 实现**：移除 aptove/swift-sdk 依赖，直接通过 Pipe + readabilityHandler 实现 JSON-RPC 2.0 over stdio 通信
2. **消息格式适配**：解析路径修正为 `params.update.sessionUpdate` + `params.update.content`（而非 SDK 假定的 `params.type`）
3. **延迟完成机制**：解决 prompt 响应先于 chunks 到达的时序问题，使用 Timer 在最后一个 chunk 后 1 秒触发 onComplete
4. **ACP 状态管理**：添加 `acpStatus` 枚举（disconnected/connecting/connected），设置页面实时显示连接状态
5. **自动启动**：AppDelegate 启动时检查 `acpAutoStart` 配置，自动连接 ACP 服务

```mermaid
sequenceDiagram
    participant App as 应用启动
    participant AI as AIService
    participant Pipe as Pipe stdio
    participant OC as opencode acp

    App->>AI: connectACP() [自动/手动]
    AI->>OC: 启动进程
    AI->>Pipe: readabilityHandler 回调
    AI->>OC: initialize (JSON-RPC)
    OC-->>Pipe: initialize 响应
    AI->>OC: session/new
    OC-->>Pipe: session 响应 + sessionId
    AI->>AI: acpStatus = .connected

    Note over AI,OC: 用户发送问题
    AI->>OC: session/prompt
    OC-->>Pipe: prompt 响应 (end_turn)
    OC-->>Pipe: session/update (agent_message_chunk)
    Pipe-->>AI: parseACPLine → handleParsedACPMessage
    AI-->>AI: onChunk(text) 流式输出
    AI-->>AI: 1s 无新 chunk → onComplete()
```
