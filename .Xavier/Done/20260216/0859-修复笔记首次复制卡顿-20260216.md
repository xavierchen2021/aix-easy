# 修复笔记首次复制卡顿

## 概述
软件启动后，第一次点击笔记列表项的复制按钮会卡顿。原因是剪贴板历史文件高达 90MB（含8张大图片截图），复制操作同步处理整个历史记录。

## 当前实现

```mermaid
sequenceDiagram
    participant U as 用户点击复制
    participant C as copyNoteToClipboard
    participant CM as ClipboardManager
    participant BG as 后台队列
    participant UI as 主线程

    U->>C: 点击复制按钮
    Note over UI: ⚠️ 以下全部在主线程同步执行
    C->>CM: copyToClipboard()
    CM->>CM: NSPasteboard.setString()
    CM->>CM: addToHistory()
    Note over CM: removeAll 遍历50项(含90MB图片)
    Note over CM: history = newHistory (@Published)
    CM->>BG: saveHistory()
    Note over BG: JSONEncoder.encode 90MB
    Note over BG: 写入90MB到磁盘
    CM->>CM: NSSound.play() (首次初始化音频系统)
    Note over UI: 全部完成后UI才响应
```

剪贴板历史分析：
- 50条记录，40条文本，8条图片，2条文件
- 单张图片最大 19.6MB，总计约 69MB
- JSON文件 90MB（base64 编码膨胀）

## 测试用例
1. 启动应用，立即点击笔记列表的复制按钮
2. **预期**：复制操作立即完成，无明显卡顿

## 方案

### 🚀 推荐方案：异步化 + 限制图片大小

```mermaid
sequenceDiagram
    participant U as 用户点击复制
    participant C as copyNoteToClipboard
    participant CM as ClipboardManager
    participant BG as 后台队列

    U->>C: 点击复制按钮
    C->>CM: copyToClipboard()
    CM->>CM: NSPasteboard.setString() ← 立即完成
    Note over CM: ✅ 按钮立即响应
    CM-->>CM: Task { addToHistory() } ← 异步延迟
    CM-->>BG: saveHistory() ← 后台
```

修改内容：
1. `copyToClipboard` 将 `addToHistory` 改为 `Task` 异步执行
2. `loadHistory` 改为异步加载，不阻塞启动
3. 捕获图片时限制最大数据 2MB，超出则跳过或压缩
4. 启动时和加载后执行一次历史清理（移除超大项）

**修改位置**：

## 任务总结与结论

通过文件引用存储和异步化处理，彻底解决了首次复制卡顿问题：

```mermaid
sequenceDiagram
    participant U as 用户点击复制
    participant C as copyNoteToClipboard
    participant CM as ClipboardManager
    participant BG as 后台队列
    participant FS as 文件系统

    U->>C: 点击复制按钮
    C->>CM: NSPasteboard.setString()
    Note over CM: ✅ 立即完成，UI无卡顿
    CM-->>CM: Task { addToHistory() }
    CM-->>BG: saveHistory()
    Note over BG: JSON仅19KB（纯文本引用）
    BG-->>FS: 图片→clipboard_cache/UUID文件
```

**核心改动**：
1. **ClipboardItem** — 自定义 Codable：encode 时非文本数据写入缓存目录文件，JSON 存文件名引用；decode 时从缓存文件加载
2. **ClipboardManager** — addToHistory 改为 Task 异步执行；loadHistory 改为后台队列异步加载；被删除项自动清理缓存文件
3. **自动迁移** — 旧格式（90MB 内联 base64）启动时自动迁移为新格式（19KB JSON + 缓存文件）

**效果**：JSON 文件 90MB → 19KB（缩小 4700 倍）
