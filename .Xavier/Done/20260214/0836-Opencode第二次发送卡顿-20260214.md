# Opencode第二次发送卡顿

## 概述
使用 Opencode ACP 协议发送消息时，第二次发送会卡很久才输出。根因是 ACP 会话/进程管理存在多个缺陷，导致使用过期连接发送请求后无响应。

## 当前实现

```mermaid
sequenceDiagram
    participant UI as AI笔记视图
    participant AIS as AIService
    participant ACP as opencode acp进程
    participant API as AI模型API

    Note over UI: 用户发送第一条消息
    UI->>AIS: sendViaOpencode()
    AIS->>AIS: ensureACPConnection()
    Note over AIS: 检查 acpProcess != nil && acpSessionId != nil
    alt 未连接
        AIS->>ACP: 启动进程 + initialize + session/new
        ACP-->>AIS: sessionId
    end
    AIS->>ACP: session/prompt (问题)
    ACP->>API: 请求AI模型
    API-->>ACP: 流式chunks
    ACP-->>AIS: session/update (chunks)
    ACP-->>AIS: prompt响应
    AIS-->>UI: onChunk + onComplete

    Note over UI,ACP: ⚠️ 间隔数小时...ACP进程可能退出/会话过期
    
    Note over UI: 用户发送第二条消息
    UI->>AIS: sendViaOpencode()
    AIS->>AIS: ensureACPConnection()
    Note over AIS: ❌ acpProcess != nil && acpSessionId != nil → 跳过重连
    Note over AIS: ❌ 未检查进程是否存活
    Note over AIS: ❌ 未检查会话是否过期
    AIS->>ACP: session/prompt → 写入死管道/过期会话
    Note over AIS: 🔴 无响应，永久挂起（无超时机制）
```

## 问题根因

1. **进程存活检查缺失**：`ensureACPConnection` 不检查 `acpProcess.isRunning`，进程退出后仍尝试复用
2. **无请求超时**：`sendACPRequest` 使用 `withCheckedThrowingContinuation` 无超时，响应不到永久挂起
3. **会话健康检查缺失**：ACP 会话可能在服务端过期，客户端无感知
4. **写死管道无保护**：`pipe.fileHandleForWriting.write(data)` 写入死管道会崩溃
5. **所有AI笔记共享一个ACP会话**：不同笔记对话混在同一会话中
6. **缺少关键日志**：prompt 响应和 chunk 接收无日志，无法追踪问题

## 方案

### 🚀推荐方案 A：完善 ACP 连接生命周期管理

```mermaid
sequenceDiagram
    participant UI as AI笔记视图
    participant AIS as AIService
    participant ACP as opencode acp进程

    Note over UI: 用户发送消息
    UI->>AIS: sendViaOpencode()
    AIS->>AIS: ensureACPConnection()
    
    alt 进程不存在 OR 进程已退出 OR 会话已过期
        AIS->>AIS: 清理旧连接
        AIS->>ACP: 启动新进程 + initialize + session/new
        Note over AIS: ✅ 记录 lastActivityTime
    end
    
    AIS->>ACP: session/prompt (带30秒超时)
    
    alt 超时
        AIS->>AIS: 断开连接 + 报错
        AIS-->>UI: onError("连接超时")
    else 正常响应
        ACP-->>AIS: chunks + response
        AIS->>AIS: 更新 lastActivityTime
        AIS-->>UI: onChunk + onComplete
    end
```

**优点**：
- 彻底解决连接过期/进程退出问题
- 超时机制防止永久挂起
- 日志完善便于调试

**缺点**：
- 会话过期后需重新建立，首次响应有几秒延迟

### 方案 B：每次发送都重建会话

**优点**：完全避免会话过期问题
**缺点**：每次发送都有几秒初始化延迟，丢失对话上下文

## 测试用例
1. 打开 AI 笔记，发送第一条消息 → 应正常流式输出
2. 等待 1 分钟后发送第二条消息 → 应正常流式输出（无卡顿）
3. 关闭应用重新打开，发送消息 → 应自动重建连接并正常输出
4. 断网后发送消息 → 应在 30 秒内报错而非永久挂起

完善了 ACP 连接生命周期管理：
