# 修复设置窗口关闭重置提醒倒计时

## 概述
打开并关闭设置窗口后，休息提醒倒计时被重置为初始值。应该只有用户修改了时间相关设置项时才重置。

## 当前实现

```mermaid
sequenceDiagram
    participant U as 用户
    participant SW as 设置窗口
    participant SWM as SettingsWindowManager
    participant RM as ReminderManager
    participant SM as SmartReminderManager

    U->>SW: 打开设置
    U->>SW: 关闭设置（未修改任何设置）
    SW->>SWM: windowWillClose
    SWM->>RM: handleSettingsClosed()
    RM->>SM: reset() ❌ 不应该重置
    RM->>SM: start()
    Note over SM: 倒计时被重置为初始值
```

## 方案

### 方案一：标记是否需要重置 ✨推荐方案

```mermaid
sequenceDiagram
    participant U as 用户
    participant SW as 设置窗口
    participant SWM as SettingsWindowManager
    participant RM as ReminderManager
    participant SM as SmartReminderManager

    U->>SW: 打开设置
    U->>SW: 关闭设置（未修改时间设置）
    SW->>SWM: windowWillClose
    SWM->>RM: handleSettingsClosed()
    RM->>RM: needsTimerReset == false
    Note over RM: 跳过重置 ✅

    U->>SW: 打开设置
    U->>SW: 修改工作时长
    SW->>RM: updateWorkDuration() → needsTimerReset = true
    U->>SW: 关闭设置
    SW->>SWM: windowWillClose
    SWM->>RM: handleSettingsClosed()
    RM->>RM: needsTimerReset == true
    RM->>SM: reset()
    RM->>SM: start()
    Note over SM: 倒计时按新设置重置 ✅
```

添加 `needsTimerReset` 标志，仅在修改时间相关配置时设为 true。

**优点：**
- 最小改动，逻辑清晰
- 不影响修改设置后的正常重置行为

## 测试用例
1. 打开设置 → 不修改任何设置 → 关闭 → 确认菜单栏倒计时未重置
2. 打开设置 → 修改工作时长 → 关闭 → 确认倒计时重置
3. 打开设置 → 修改休息时长 → 关闭 → 确认倒计时重置

## 任务总结与结论

在 `ReminderConfig` 中添加 `needsTimerReset` 标志位，仅当用户修改了工作时长、休息时长、空闲阈值、休息认定时间这四个时间相关设置时才将标志设为 true。`handleSettingsClosed()` 根据标志决定是否执行 reset+start，未修改则跳过。

```mermaid
flowchart TD
    A[设置窗口关闭] --> B{needsTimerReset?}
    B -->|false| C[跳过重置，打印日志]
    B -->|true| D[reset + start 计时器]
    D --> E[needsTimerReset = false]
```
