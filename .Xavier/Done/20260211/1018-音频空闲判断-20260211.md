# 音频空闲判断

## 概述
在用户停止键鼠输入后，空闲计时开始的前 5 秒内检测是否存在连续的音频输出；若连续 5 秒都有音频响度，则判定为“看视频/听音频”，暂停工作计时并冻结空闲计时，直到键鼠恢复后再继续工作计时。

## 当前实现
```mermaid
flowchart TD
    A[键鼠输入事件] --> B{是否空闲}
    B -- 否 --> C[累加工作活跃时间]
    B -- 是 --> D[记录空闲开始时间]
    D --> E{空闲是否超过阈值}
    E -- 否 --> C
    E -- 是 --> F[进入暂停/休息判定]
    F --> G[触发休息计时与蒙版]
```

## 方案
### 方案一：在空闲开始后 5 秒内做音频采样，连续有声则进入“视频模式”（推荐方案✅）
```mermaid
flowchart TD
    A[键鼠停止] --> B[空闲计时开始]
    B --> C{前 5 秒连续有声?}
    C -- 是 --> D[进入视频模式: 暂停工作计时 & 空闲计时冻结在 5 秒]
    C -- 否 --> E[继续原空闲阈值判断]
    D --> F[键鼠恢复]
    F --> G[退出视频模式, 恢复工作计时与空闲计时]
```
优点：
- 与现有计时模型兼容，不影响休息逻辑
- 仅在空闲初期判断，符合需求且实现简单
- 可通过统一音频检测工具复用

缺点：
- 依赖系统音频计量能力，部分设备可能不支持峰值读数

### 方案二：在空闲期间持续轮询音频，任意时刻连续 5 秒有声即进入视频模式
```mermaid
flowchart TD
    A[键鼠停止] --> B[空闲计时开始]
    B --> C[持续音频轮询]
    C --> D{连续 5 秒有声?}
    D -- 是 --> E[进入视频模式]
    D -- 否 --> F[继续轮询]
    E --> G[键鼠恢复]
    G --> H[退出视频模式]
```
优点：
- 对“稍后开始播放音频”的场景更敏感

缺点：
- 与需求“前 5 秒内判断”不完全一致
- 空闲时间越长，误判概率越高

## 测试用例
1. 停止键鼠操作，确保前 5 秒无音频输出，确认仍按原逻辑累加空闲时间并按阈值进入休息。
2. 停止键鼠操作，同时连续播放音频 5 秒，确认进入视频模式：工作计时暂停、空闲时间冻结。
3. 视频模式下恢复键鼠操作，确认工作计时继续、空闲时间恢复为实时显示。
4. 空闲 5 秒内断续有声（非连续），确认不进入视频模式。
