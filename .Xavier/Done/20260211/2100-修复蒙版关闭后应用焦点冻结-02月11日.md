# 修复蒙版关闭后应用焦点冻结

## 概述
蒙版出现后，点击按钮关闭蒙版时，会导致程序处于被冻结的状态，无法滚动，无法聚焦输入框，用户需要手动点击其他窗口后再点回来才能恢复正常。

```mermaid
    App->>App: 应用获得焦点

    Note over User,Previous: 蒙版关闭流程（当前实现）
    
    User->>Overlay: 点击按钮
    Overlay->>Overlay: dismiss()
    Overlay->>Overlay: orderOut(nil)
    Overlay->>Overlay: removeEventMonitors()
    Note over Overlay: ❌ 没有恢复应用焦点
    Note over Previous: ❌ 之前的窗口没有恢复
    Note over App: ❌ 应用处于无焦点状态
    Note over User: ⚠️ 无法滚动、无法聚焦输入框
```

### 问题分析

在 [ReminderOverlayWindow.swift](vscode://file/Volumes/Cache/X/Sources/View/ReminderOverlayWindow.swift:203) 的 `dismiss()` 方法：

```swift
func dismiss() {
    orderOut(nil)
    removeEventMonitors()
    onDismiss()
    onContinue?()
}
```

**问题点**：
1. 蒙版显示时调用 `makeKeyAndOrderFront(nil)` 和 `NSApp.activate(ignoringOtherApps: true)` 抓取焦点
2. 虽然窗口设置了 `canBecomeKey = false`、`canBecomeMain = false`，但应用仍获得了焦点
3. 关闭时只调用 `orderOut(nil)` 隐藏窗口，没有恢复焦点到之前的窗口
4. 导致应用处于"激活但无关键窗口"的状态，无法响应键盘和滚动事件

## 方案

### 方案A：保存并恢复之前的 Key Window

```mermaid
flowchart TD
    A[蒙版 show 时] --> B[保存 NSApp.keyWindow]
    B --> C[保存 previousKeyWindow]
    C --> D[makeKeyAndOrderFront & activate]
    
    E[蒙版 dismiss 时] --> F{previousKeyWindow 存在?}
    F -->|是| G[previousKeyWindow.makeKeyAndOrderFront]
    F -->|否| H[尝试激活主窗口或设置窗口]
    
    G --> I[清空 previousKeyWindow]
    H --> I
```

**优点**：
- 精确恢复到用户操作前的窗口状态
- 用户体验最佳，无需手动重新聚焦

**缺点**：
- 需要新增属性保存窗口引用
- 窗口可能在蒙版显示期间被关闭，需要处理边界情况

### 🚀 推荐方案：在 dismiss() 中激活主应用窗口

```mermaid
flowchart TD
    A[蒙版 dismiss 时] --> B[orderOut 关闭蒙版]
    B --> C[removeEventMonitors 清理监听]
    C --> D{查找主窗口}
    D -->|找到设置窗口| E[settingsWindow.makeKeyAndOrderFront]
    D -->|未找到| F[遍历所有窗口]
    F --> G{找到可见的普通窗口?}
    G -->|是| H[window.makeKeyAndOrderFront]
    G -->|否| I[NSApp.activate 激活应用]
    
    E --> J[激活成功]
    H --> J
    I --> J
    
    J --> K[onDismiss 回调]
    K --> L[onContinue 回调]
```

**优点**：
- 不需要保存额外的窗口引用
- 自动查找合适的窗口激活
- 兼容窗口被关闭的情况
- 代码简洁，易于维护

**缺点**：
- 可能不是用户操作前的窗口（但大部分情况下设置窗口就是操作前的窗口）

### 方案C：简单调用 NSApp.activate

```mermaid
flowchart TD
    A[蒙版 dismiss 时] --> B[orderOut 关闭蒙版]
    B --> C[removeEventMonitors 清理监听]
    C --> D[NSApp.activate]
    D --> E{系统自动选择窗口}
    E --> F[可能激活任意窗口]
    F --> G[onDismiss 回调]
```

**优点**：
- 代码最简单，只需一行

**缺点**：
- 依赖系统自动选择窗口，不可控
- 可能激活非预期的窗口（如笔记窗口、浏览器选择窗口等）
- 用户体验不佳

## 任务总结与结论

使用推荐方案B，在 `dismiss()` 方法中添加窗口激活逻辑。修改后蒙版关闭时会自动查找合适的窗口并激活焦点，解决了应用冻结问题。

**最终实现**：

```swift
func dismiss() {
    orderOut(nil)
    removeEventMonitors()
    
    // 恢复焦点到主窗口
    Task { @MainActor in
        // 优先恢复到偏好设置窗口（用户最常交互的窗口）
        if let settingsWindow = NSApp.windows.first(where: { window in
            window.isVisible && 
            window.title.contains("偏好设置") && 
            window != self
        }) {
            settingsWindow.makeKeyAndOrderFront(nil)
            print("🔄 蒙版关闭，恢复焦点到: 偏好设置窗口")
        } else if let visibleWindow = NSApp.windows.first(where: { window in
            window.isVisible && 
            window.canBecomeKey && 
            window != self &&
            window.level == .normal
        }) {
            visibleWindow.makeKeyAndOrderFront(nil)
            print("🔄 蒙版关闭，恢复焦点到: \(visibleWindow.title)")
        } else {
            NSApp.activate(ignoringOtherApps: true)
            print("🔄 蒙版关闭，激活应用")
        }
    }
    
    onDismiss()
    onContinue?()
}
```
