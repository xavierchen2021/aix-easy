# 方案分析：笔记输入光标默认状态垂直居中修复

## 1. 需求说明
- **需求问题**：笔记项在刚进入输入状态（默认内容为空或初始准备输入时），输入框中的闪动光标没有垂直居中（偏上贴顶）；只有当输入了一行内容后，光标和文字才在垂直方向恢复居中。
- **目标效果**：无论笔记内容是否为空、刚进入编辑闪动光标还是输入了一行/多行内容，光标与文本在垂直方向上均始终保持自然、准确的居中排版对齐，无跳跃感。

---

## 2. 现状排查与根因分析

### 2.1 现象定位与根因
1. **容器高度与单行字高的落差**：
   - 在 `Sources/View/NoteListView.swift` 的 `NoteItemView` 中，空笔记展示“新笔记...”占位文字时，SwiftUI 的 `Text` 组件因默认行距和内边距测算出的 `displayHeight` 约为 21~22pt。
   - 双击进入编辑时，`contentHeight` 被赋值为 `displayHeight`（21~22pt），使得外层 `CustomTextEditor` 的高度为 21~22pt。
2. **NSTextView 顶部对齐特性**：
   - `CustomTextEditor` 内部封装的是 AppKit 的 `NSTextView`。
   - 在 macOS AppKit 中，`NSTextView` 的文本容器和光标默认贴着左上角 `(0, 0)` 绘制，`textContainerInset` 为 0。
   - 13pt 系统字体的实际光标/字高约为 15.5~16pt。在 21~22pt 的容器中，光标贴顶闪烁，底部留有约 6pt 空白，产生明显的“光标偏上、未垂直居中”的视觉错位。
3. **输入一行内容后为何居中**：
   - 用户敲入文字后，触发 `textDidChange` -> `updateHeight()`。
   - `layoutManager.usedRect(for: textContainer)` 计算出实际单行文本紧凑高度（约 16pt），并将 `contentHeight` 缩减为 16pt。
   - 外层 `HStack` 在垂直方向将 16pt 的输入框与左侧 16pt 的复选框居中对齐，才使得光标和文字恢复居中。

### 2.2 解决方案
1. **重写 NSTextView 的 textContainerOrigin 实现智能垂直居中**：
   - 自定义 `VerticallyCenteredTextView: NSTextView`，重写 `textContainerOrigin`：
     ```swift
     class VerticallyCenteredTextView: NSTextView {
         override var textContainerOrigin: NSPoint {
             let origin = super.textContainerOrigin
             guard let layoutManager = self.layoutManager,
                   let textContainer = self.textContainer else {
                 return origin
             }
             layoutManager.ensureLayout(for: textContainer)
             let usedRect = layoutManager.usedRect(for: textContainer)
             var contentHeight = usedRect.height
             if string.isEmpty || contentHeight < 1 {
                 if let font = self.font {
                     contentHeight = layoutManager.defaultLineHeight(for: font)
                 } else {
                     contentHeight = 16
                 }
             }
             let dy = (bounds.height - contentHeight) / 2
             return NSPoint(x: origin.x, y: max(0, floor(dy)))
         }
     }
     ```
   - 无论容器高度是 18、20 还是 22pt，文本容器（含光标和文字）会自动在可用高度中垂直居中（`dy = (bounds.height - contentHeight) / 2`）。
   - 当多行或高度达到上限时，`dy <= 0` 自动回到顶部对齐正常滚动，兼容性极佳。
2. **初始化高度与编辑切换协同**：
   - 在 `CustomTextEditor` 的 `makeNSView` 中使用 `VerticallyCenteredTextView`。
   - 在进入编辑时，若 `content.isEmpty`，将初始 `contentHeight` 统一规范为单行紧凑高度（18pt），并在组件挂载时主动刷新一次布局，彻底根除偏顶闪动问题。
