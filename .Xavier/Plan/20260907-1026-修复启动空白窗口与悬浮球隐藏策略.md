# 方案分析：修复启动空白窗口与悬浮球隐藏策略调整

## 1. 需求说明
1. **启动空白窗口修复**：应用启动时桌面上会出现一个无标题、无内容的空白小窗口，排查根因并彻底消除该窗口。
2. **悬浮球隐藏同步修复**：修复悬浮球隐藏状态不同步的缺陷，确保新添加的悬浮球在全局隐藏或配置刷新时，能够严格与整体显隐状态保持同步，不发生意外弹出或遗漏。
3. **笔记列表展开显隐策略调整**：调整点击悬浮球展开笔记列表时的行为，去除原先“展开笔记时隐藏其他悬浮球”的策略，保持所有其他悬浮球正常显示。

---

## 2. 现状排查与根因分析

### 2.1 启动空白小窗口根因
- **排查定位**：
  `Sources/App/FloatingButtonApp.swift`:
  ```swift
  @main
  struct FloatingButtonApp: App {
      @NSApplicationDelegateAdaptor(AppDelegate.self) var appDelegate
      
      var body: some Scene {
          Window("AIX", id: "main") {
              EmptyView()
          }
          .windowResizability(.contentSize)
          .defaultSize(width: 0, height: 0)
      }
  }
  ```
- **根因**：
  macOS SwiftUI 应用启动时，Scene 中的 `Window("AIX", id: "main")` 会被系统默认实例化并创建一个窗口显示出来。而本项目的所有功能窗口（悬浮球 `FloatingWindow`、笔记 `NoteWindow`、设置窗口、状态栏菜单）都是在 `AppDelegate` 中通过 AppKit 自主管理的辅助窗口（`NSPanel`/`NSWindow`），根本不需要 SwiftUI 的主窗口。
- **解决方案**：
  将 `Window("AIX", id: "main") { EmptyView() }` 替换为 `Settings { EmptyView() }`。`Settings` 场景在 App 启动时不会自动创建窗口显示，仅在触发偏好设置快捷键时响应（而本项目的偏好设置由 `SettingsWindowManager` 独立管理），彻底根除启动空白窗口。

### 2.2 悬浮球隐藏与新增球不同步根因
- **排查定位**：
  `Sources/App/AppDelegate.swift` 中的 `refreshAllWindows()`：
  ```swift
  // 刷新现有窗口
  for (index, window) in floatingWindows.enumerated() {
      ...
      // 确保窗口可见
      if index < config.buttonCount {
          window.orderFrontRegardless()
      }
  }
  ```
- **根因**：
  1. 当悬浮球处于全局隐藏（`globalHiddenState == true`）或用户主动右键隐藏了某个悬浮球（`isButtonHiddenByUser == true`）时，一旦触发 `refreshAllWindows()`（例如通过菜单栏新增悬浮球、在设置修改了外观配置等），代码对所有 `floatingWindows` 无条件执行了 `window.orderFrontRegardless()`！这导致原本隐藏的悬浮球被强行重新显示出来。
  2. 新增悬浮球追加到 `floatingWindows` 数组后，紧接着进入此循环也被强制显示，破坏了全局隐藏状态。
  3. 删除悬浮球时（`deleteFloatingButton`），`userHiddenButtonIndices` 缺少索引重排逻辑，导致索引偏移错乱。
- **解决方案**：
  1. 重构 `refreshAllWindows()` 中的窗口显隐逻辑：严格按照 `let shouldShow = !isGlobalHidden && !isUserHidden` 进行状态判定，`shouldShow` 为 `true` 时调用 `orderFrontRegardless()`，为 `false` 时调用 `orderOut(nil)`。
  2. 在新增悬浮球时，保持当前全局隐藏状态约束。
  3. 在删除悬浮球时，同步更新 `userHiddenButtonIndices` 集合（移除被删索引，大于该索引的减 1）。
  4. 在状态栏菜单的悬浮球二级菜单中，为每个悬浮球提供与当前可见状态匹配的“隐藏悬浮球 / 恢复悬浮球”操作，提升控制灵活性。

### 2.3 笔记列表展开显隐策略调整
- **排查定位**：
  `Sources/App/AppDelegate.swift` 中的 `toggleNoteWindow(...)`：
  ```swift
  // 面板打开后隐藏同分组的其他悬浮球
  hideGroupFloatingWindows(for: buttonIndex, except: attachedWindow)
  ```
  以及收起笔记面板时：
  ```swift
  showGroupFloatingWindows(for: buttonIndex)
  ```
- **根因与现状**：
  现有策略会在展开笔记面板时调用 `hideGroupFloatingWindows` 将同组或其余悬浮球隐藏，关闭面板时再调用 `showGroupFloatingWindows` 重新显示。
- **解决方案**：
  1. 移除 `toggleNoteWindow` 展开时的 `hideGroupFloatingWindows` 调用，保持所有悬浮球的显示状态。
  2. 移除收起笔记时的 `showGroupFloatingWindows` 调用，避免产生不必要的窗口层级刷新。
  3. 清理无用的 `hideGroupFloatingWindows` 关联逻辑，简化 `toggleFloatingWindow` 中的判定（无需再假定笔记窗口打开时其他球全可见）。

## 4. 循环评审设计 (Review Design)
- **核心关注点**：
  1. 启动时是否还有任何多余的空白窗口出现；
  2. 点击悬浮球展开笔记列表后，其他悬浮球是否完整保留在桌面上、可正常交互；
  3. 全局隐藏（快捷键/菜单栏）所有悬浮球后，添加新悬浮球是否保持隐藏；解除隐藏后是否全部正常恢复。
- **评审方式**：通过 `ask_question` 确认方案后实施代码修改，完成后提供 DMG 与测试指引供用户测试验证。
