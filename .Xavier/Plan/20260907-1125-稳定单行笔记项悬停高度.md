# 方案分析：稳定单行笔记项悬停时的高度

## 1. 需求说明
- **需求问题**：鼠标悬停在单行文字的笔记项上触发右侧浮动操作按钮组（移动分组、复制、删除）滑出后，会导致卡片高度轻微变高；鼠标移开后卡片高度又变矮，导致卡片和列表发生明显的垂直跳动。
- **目标效果**：确保单行文字的笔记项在平时未悬停与鼠标悬停划出操作按钮时，高度完全保持恒定一致，消除跳动感。

---

## 2. 现状排查与根因分析

### 2.1 根因定位
在 `Sources/View/NoteListView.swift` 的 `NoteItemView` 中：
```swift
HStack(spacing: 12) {
    // 1. 复选框: 16pt
    Button(...) { Image(...).font(.system(size: 16)) }
    
    // 2. 文本内容区
    Text(...) // 单行系统字体高度约为 16pt
    
    // 3. 右侧按钮组 (isHovered 为 true 时才出现)
    if isHovered {
        HStack(spacing: 8) {
            Menu { ... } label: { Image(systemName: "folder.badge.gearshape") }
                .fixedSize()
            Button(...) { Image(systemName: "doc.on.doc") }
            Button(...) { Image(systemName: "trash") }
        }
    }
}
.padding(.vertical, 8)
```
- **未悬停状态**：HStack 仅包含复选框与单行文本，子视图最大高度约为 16pt，外加上下各 8pt padding，卡片总高约为 32pt。
- **悬停状态**：右侧按钮组中的 `Menu` 及系统图标在 macOS 默认样式下占据约 20~22pt 的点击排版高度。当按钮组出现时，整行 `HStack` 的高度被瞬间从 16pt 顶高到 20~22pt，卡片总高增至 36~38pt。
- **差异结果**：对于 2 行以上的长笔记，文本本身高度（>=32pt）大于按钮高度，因此不发生跳动；但对于单行笔记，按钮高度大于文本高度，导致出现明显的“悬停变高、移开变矮”的抖动。

### 2.2 解决方案
1. **统一单行卡片内容基准高度（minHeight: 20）**：
   在 `NoteItemView` 的主体内容行 `HStack(spacing: 12)` 上设定 `.frame(minHeight: 20)`。
   使得未悬停时单行笔记的内容高度基准即为 20pt。
2. **规范右侧浮动按钮组尺寸**：
   为右侧按钮组中的图标指定统一字号与排版高度（`.font(.system(size: 13))`，并给按钮容器设置 `.frame(height: 20)`），确保其高度严格不大于 20pt。
3. **消除高度差**：
   未悬停时高度 = 20 + 8*2 = 36pt；
   悬停划出按钮后高度 = 20 + 8*2 = 36pt。
   两者分毫不差，单行笔记项的高度在划入划出时绝对稳定。
